# Installazione e test — 0.7.3

1. Fai una copia di sicurezza. Chiudi Visual Studio, editor e Hub. Estrai la patch nella cartella contenente `CMakeLists.txt`, mantenendo i percorsi e sostituendo solo i file presenti nello ZIP. La patch presuppone la versione 0.7.2 con API tipizzate.
2. In Visual Studio Installer verifica il carico di lavoro Sviluppo desktop .NET e gli strumenti C#. Installa anche l’SDK .NET 8 x64 (non solo il runtime), conservando l’SDK .NET 10. `dotnet --list-sdks` deve mostrare sia 8.x sia 10.x. Visual Studio 2022 deve essere aggiornato.
3. Dalla radice del motore esegui `.\scripts\build-editor.ps1 -Configuration Release`. Controlla che esista `build/export-templates/windows-x64/Release/runtime-template.json`. Non spostare una vecchia cache CMake da un’altra cartella.
4. Apri Hub/editor Release con i rispettivi script e il parametro `-Configuration Release`. Apri un progetto esistente, premi Assets > Refresh IDE project, quindi fai doppio clic su uno script. Non è necessario ricreare il progetto.
5. In Esplora soluzioni verifica GameScripts e TwoDog.API e le cartelle degli script. Non devono comparire progetti scaricati o errori di framework/riferimenti. In uno script derivato da Behaviour aggiungi `using TwoDog;` e verifica Ctrl+Spazio su `Entity.GetComponent<Rigidbody2D>()`, `SpriteRenderer` e `UIText`; su una variabile Rigidbody2D verifica suggerimenti per `Velocity` e `AddForce`.
6. Premi F12 su Rigidbody2D: deve aprire la definizione API. Crea uno script in una sottocartella dall’editor, aprilo e verifica il suo percorso nell’IDE. Ripeti con Visual Studio inizialmente chiuso e poi già aperto.
7. Salva una modifica valida, torna all’editor e verifica ricompilazione automatica e Play. Verifica che i file runtime compaiano in `.twodog/cache/scripts/runtime` e che IntelliSense continui a funzionare dopo la build. Introduci temporaneamente un errore C#, controlla il log, quindi correggilo.
8. Apri File > Build for Windows. Scegli il template Release del punto 3 e una cartella di output esterna al progetto e ai sorgenti engine. Esporta, verifica stato/log e avvia il gioco. Riapri il pannello e verifica le impostazioni salvate.
9. Nel pacchetto verifica assenza di `.twodog`, GameScripts.sln, sorgenti .cs, Hub ed editor. Prova anche una macchina Windows x64 senza SDK .NET: il runtime è incluso; servono driver OpenGL compatibili.
10. Introduci un errore C# ed esporta nuovamente: deve fallire conservando la build precedente. Correggi lo script. Una destinazione interna al progetto o all’engine deve essere rifiutata.
11. Per le verifiche automatiche esegui `.\scripts\verify.ps1 -Configuration Debug`. Il nuovo controllo workspace compila una soluzione .NET 8, verifica il riferimento API del compilatore design-time, compila il progetto runtime .NET 10 e controlla che gli intermedi IDE siano invariati.
12. Inviami i punti riusciti/falliti e, in caso di problemi IDE, `.twodog/logs/ide.log` e gli errori di caricamento progetto di Visual Studio. La lista di suggerimenti IntelliSense è distinta dai suggerimenti predittivi IntelliCode: questa patch corregge riferimenti, framework e soluzione, non configura estensioni AI dell’IDE.
