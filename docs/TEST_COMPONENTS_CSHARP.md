# Test locali — componenti e API C# 0.7.2

1. Chiudi editor e Hub. Applica la cartella 2Dog della patch sopra i sorgenti 0.7.1, mantenendo i percorsi. Sono incluse anche le correzioni per cwctype e Inside dell'export. Non occorre ricreare il progetto di gioco. Se hai modifiche personali ai file sostituiti, confrontale prima.
2. Compila con `./scripts/build-editor.ps1 -Configuration Debug`. Questa build aggiorna anche le DLL C# dell'host e le sorgenti API usate da Visual Studio. Non copiare soltanto Components.cs nella cartella assets del gioco: appartiene all'API del motore.
3. Esegui `./scripts/verify.ps1 -Configuration Debug`. Oltre alle prove esistenti, devono passare cinque test components e la riga TYPED COMPONENT CHECKS: 13 passed. Per ripetere solo il gruppo nativo: `ctest --test-dir build/cmake/windows-csharp -C Debug -L components --output-on-failure`. Per ripetere solo il nuovo gruppo C#: `dotnet run --project managed/ComponentChecks/ComponentChecks.csproj -c Debug`.
4. Avvia l'editor. Crea un oggetto e aggiungi SpriteRenderer, Rigidbody2D, un collider aggiuntivo, Animator e World Text. Controlla che i valori iniziali siano presenti e che Apply, Undo e Redo funzionino. Elimina il collider aggiuntivo se non ti serve per la demo.
5. Nel collider prova radius negativo per una circle o halfSize zero per una box; prova anche density negativa. Apply deve rifiutare la modifica senza alterare la scena valida o aggiungere un passo Undo. Ripristina valori validi e riprova. Una copia di una scena con gli stessi dati invalidi deve essere rifiutata al caricamento.
6. Crea una Label con nome ScoreLabel. Prova un fontScale pari a zero, poi un valore valido. Il primo Apply deve essere rifiutato; il secondo deve riuscire. Controlla anche Canvas e Button già presenti nella tua scena.
7. Crea lo script TypedComponentsDemo.cs dalla sezione Assets, aprilo in Visual Studio e inserisci il codice dell'esempio in managed/GameScripts/TypedComponentsDemo.cs. In Esplora soluzioni deve essere disponibile EngineAPI/Components.cs e l'autocompletamento di RequireComponent<Rigidbody2D>(), SpriteRenderer e UIText.
8. Salva lo script e aspetta la compilazione riuscita. Assegnalo a un oggetto con body Dynamic e sprite, senza un altro controller che ne modifichi la velocità. Usa un progetto con azioni left/right configurate, come le demo. Premi Play: l'oggetto deve cambiare colore e muoversi orizzontalmente; ScoreLabel, se presente, deve aggiornare il tempo.
9. Modifica il colore o la velocità nell'esempio, salva e verifica il reload secondo il comportamento attuale del progetto. Dopo Stop, le modifiche runtime a testo e colore non devono sostituire i valori della scena salvata.
10. Su un oggetto privo di body, GetComponent<Rigidbody2D>() deve restituire null e TryGetComponent deve restituire false. RequireComponent deve segnalare il componente mancante in Console. UIText su una Image deve risultare assente; su Label e Button deve essere disponibile.
11. Verifica che i vecchi script basati su Entity.Velocity, Entity.Component e UI.Text funzionino ancora. Ricompila Release, esporta con Build for Windows e controlla movimento e testo anche nel gioco esportato.
12. Riporta F/N con il numero del punto. Per problemi di compilazione allega il primo errore completo, non soltanto il messaggio conclusivo Build failed.
